# iOS SDK 0.1.7 — retain authorized passkey credentials

- Keep a valid credential returned by Apple's authorization delegate even if
  SwiftUI replaces the presentation anchor or the scene changes afterward.
  Window checks remain in place before requesting native presentation.
- Emit `fido2_proof` with a populated credential response and the exact incoming
  `authenticationId` / `correlationId`. Reject empty or incomplete proofs before sending.
  Registration carries `attestationObject`; authentication carries `signature`
  and `authenticatorData`. Both carry `id` and `clientDataJSON`.
- Preserve original presentation-anchor, foreground-scene and visible-window
  diagnostics when the coordinator reports a failure. Different errors do not
  inherit an earlier check. Diagnostics remain opt-in and redact credentials.
- Ignore stale native completion after cancellation. Successful proof delivery
  remains pending until the bank verifies it; it does not authorize a transaction locally.
- No UI controls, public API parameters or call protocol changes are added.

Upgrade the package requirement to exact version **0.1.7**, resolve packages,
rebuild and distribute the host app. Existing `passkeys` configuration continues
working. Enable `diagnosticsEnabled: true` during the customer retest, then disable
it after investigation. Domain association and signed app entitlements remain
host-app prerequisites.
