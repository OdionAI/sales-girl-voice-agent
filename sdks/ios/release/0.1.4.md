# 0.1.4 — Native passkey confirmation

Includes native passkey confirmation and the SDK-brief Revision 2 contract
update. Configure it entirely in application code; the sample adds no controls.

- Configure passkeys through `AttentiveAgentView` or `AttentiveCall` in code.
  Existing `audioInput` configuration remains available. No settings UI is added.
- Present native assertion and registration requests over the call's own window.
  Each mode serializes its own credential response using unpadded base64url.
- Keep action authentication pending until a correlated backend result explicitly
  accepts the proof. Authentication acceptance and transaction completion remain
  separate. No spoken or typed confirmation can replace protected authorization.
- Follow Revision 2 correlation and expiry requirements without an additional
  acknowledgement handshake. Reject unsupported native credential requirements
  explicitly; preserve supported verification preferences and prompt time limits.
- Invalidate late callbacks on call end, expiry and reconnect. Cancellation keeps
  the call usable. No automatic prompt retries or proof reuse are performed.
- The headless core supports iOS 16; supplied UI requires iOS 17. Registration
  exclusion lists require iOS 17.4 and fail explicitly on older versions.

Host applications need their own associated-domain entitlement and approval in
the bank's domain association file. See [integration notes](../PASSKEYS.md).
The SDK does not obtain hardware identifiers or call the bank directly.

Before enabling bank transactions in production, confirm the bank's relying
parties, accepted proof encoding/schema, device identifier semantics, registration
authorization policy
and synced/device-bound credential expectations. Test native passkeys on a real
iPhone with the bank's test account. Simulated ceremonies and native request
mapping tests do not establish bank acceptance.
