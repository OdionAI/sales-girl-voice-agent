# Attentive iOS SDK 0.1.0-staging.2

Private prerelease. Replaces the package layout in 0.1.0-staging.1; the two
customer-facing modules and call API remain compatible.

## Package Contents

- `Package.swift`, four binary XCFrameworks, required third-party notices.
- Public modules: `AttentiveVoice`, optional `AttentiveVoiceUI`.
- Private dynamic runtimes: `AttentiveMedia`, `AttentiveBindings`.
- iPhone arm64 and iOS Simulator arm64/x86_64 slices only.
- No Markdown, guides, agent instructions, samples, or implementation sources.
- Privacy manifests and UI resources are preserved. Required attribution is
  preserved and packaging modifications are disclosed in `Packaging-NOTICE`.

Human and coding-agent guides stay in the internal source repository. Build
provenance and SHA256SUMS are generated beside the package, not inside it.
Renaming private frameworks removes upstream names from the package navigator
and dynamic-loader paths, not from licensing or all inspectable native symbols.
This is implementation encapsulation, not a guarantee of reverse-engineering
resistance. The transport, native exported ABI, server, models and auth behavior
are unchanged by packaging.

Includes the previously tested typed `CallError.insufficientCredits` and readable
UI billing alerts. Existing calls do not need a different endpoint or bootstrap.

## Rebuild and Verify (Internal)

From `sdks/ios`:

```sh
node script/build_binary_release.mjs
node script/verify_binary_release.mjs .build/binary-release-0.1.0-staging.2/package
node script/check_documentation.mjs .build/binary-release-0.1.0-staging.2/package
```

The build updates framework bundle names, Mach-O install names/dependencies,
private module maps and ad-hoc signatures. Native exports are compared against
the pinned upstream artifacts for every shipped architecture. Upstream source
and the ordinary development package are not renamed or changed.

Before publishing, build and run a fresh consumer of the exact binary package,
verify greeting audio and a chat-driven reply through the public endpoint,
and build a signed physical-device consumer. Do not overwrite the old release.
Host apps sign the embedded binaries; this prerelease is not publisher-signed
and is not a claim of completed App Store or production banking certification.
