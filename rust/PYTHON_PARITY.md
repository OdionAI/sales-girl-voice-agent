## Native RNNoise checkpoint

The selected RNNoise path uses the maintained [`rnnoise2`](https://crates.io/crates/rnnoise2) crate (v0.1.2), which builds the vendored **Xiph RNNoise v0.2** C sources (xiph/rnnoise commit `70f1d25`) with the same default model the Python worker's `pyrnnoise` wraps (`0a8755f8…`, fetched and checksum-pinned by `rnnoise2-sys` at build time), through the official LiveKit resampler at 16→48→16 kHz. `rnnoise2`/`rnnoise2-sys` pin the identical commit and model we previously vendored by hand, so it is a byte-for-byte DSP equivalent. No Python process or model server runs in suppression. PCM16 amplitude is preserved at the neural boundary. Invalid output fails open with original caller audio. Source allowlist selection, whitespace trimming and case sensitivity match independently exported Python cases.

Native checks verify real filtering/probability output, exact output duration including the final partial frame, arbitrary packet partition invariance, isolated call state and unchanged unselected audio. The earlier pure-Rust `nnnoiseless` 0.5.2 path was a port of the obsolete RNNoise v0.1 model: measured on identical 48 kHz signals it barely attenuated steady background noise (loud white noise gain ≈0.83) and scored a pure 440 Hz tone as speech (probability ≈0.98), so ambient noise still tripped the RMS speech gate and interrupted the agent. RNNoise v0.2 attenuates the same signals (loud noise gain ≈0.001, tone ≈0.08) and matches the pinned `pyrnnoise` 0.4.5 reference to three decimal places (e.g. tone gain 0.0807 both; noisy-speech gain 0.457 both). Remaining divergence from Python is only packet-boundary handling: Python's non-flushing path yields 15,824 samples for 16,000 silent input samples, while native retains the input duration. Real speech/ASR quality and provider comparisons remain required.
